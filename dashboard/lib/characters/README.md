# AgencyForge Character System

The master character library lives at:

`character-library`

Those files are the source of truth. This library references them but does not copy, rewrite, replace, or regenerate them.

## Public API

UI code should request characters through:

```ts
import { CharacterRegistry } from "@/lib/characters";

const ceo = CharacterRegistry.get("ceo");
const dashboardCharacters = CharacterRegistry.forScreen("dashboard");
const changedCharacters = CharacterRegistry.react({
  type: "revenue.changed",
  value: 120000,
  previousValue: 90000,
});
```

Do not import character images directly inside UI components.

## Runtime Model

- `CharacterRegistry` is the public singleton for screens and components.
- `CharacterManager` owns registration, state changes, asset resolution, and emotional rule evaluation.
- `src/assets/characters/manifest.ts` is generated by the asset pipeline and is the runtime source for exported PNG paths.
- `EmotionRules.ts` is the data-driven business event-to-character-state mapping.
- `screenCharacterMap.ts` maps screens to character IDs.
- Placeholder characters use `placeholder://characters/...` until a real master sheet exists.

Generated future variations should be registered with the manager as `generated-variation` assets only for the missing pose, expression, or animation. The original master sheet remains untouched.
